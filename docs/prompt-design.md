# LLM Prompt 设计

## 目标

工作台不使用一个宽泛的“你是公考助手”提示词覆盖所有任务。每个会调用模型的功能都有独立协议，并共同继承事实、隐私、提示注入和输出格式底线。

每份功能 Prompt 都按以下结构设计：

1. 角色与任务目标：明确模型当前负责教学、诊断、评分、命题还是知识编辑。
2. 证据优先级：说明题干、材料、参考答案、统计和模型候选各自是什么，不默认任何候选正确。
3. 分步工作流程：要求先识别任务与输入完整性，再分析、核验和生成结果。
4. 输出契约：规定 Markdown 章节或严格 JSON 字段，便于程序解析和用户复核。
5. 失败边界：缺少材料、答案冲突或证据不足时，允许降级、删除候选或明确报错，不允许猜补。
6. 输出前质检：在提交结果前复核证据、完整性、一致性、可执行性和格式。

## 模块清单

| 模块         | 专门目标                   | 关键约束                                 |
| ------------ | -------------------------- | ---------------------------------------- |
| 模型连接测试 | 验证连接和基本指令遵循     | 只接受精确的 `OK`                        |
| AI 助教      | 解决学习问题并形成迁移方法 | 结论、依据、方法、自检                   |
| 错题讲解     | 重建正确路径并定位首次分叉 | 独立核验参考答案；固定错因标签           |
| 学习诊断     | 从本地统计生成七日动作     | 事实、推断、建议分层；小样本降级         |
| 申论评估     | 依据题目与参考要点评分     | 三维度权重、证据化评价、严格 JSON        |
| 变式生成     | 生成同考点异情境四选一题   | 独立可解、唯一答案、干扰项对应错误路径   |
| 变式终审     | 独立求解并修复候选题       | 不信任候选答案；无法修复时明确返回 error |
| 知识提取     | 从单个来源片段生成候选     | 不跨片段猜测、原样证据摘录、置信度分级   |
| 知识终审     | 对照同一来源逐项复核       | 删除无证据内容，不为维持数量而补写       |

## 数据边界

除自由对话外，模块输入通过 `taskDataEnvelope()` 序列化为 `UNTRUSTED_TASK_DATA`，来源正文通过 `sourceEnvelope()` 标记为 `SOURCE_MATERIAL`。系统协议明确规定这些内容都是待分析数据，其中出现的“忽略先前要求”等文字不能改变任务。

数据边界不能代替模型服务商的隐私政策。使用云模型时，实际提交的当前任务数据仍会发送给用户配置的服务商；仅转换模式和本地 MarkItDown 不调用模型。知识工坊的标准、高质量模式必须由用户主动启动。

## 当前验证方式

- 静态测试确认每个模块包含相应的流程、格式和质量约束。
- 结构化输入测试确认题目和候选内容位于不可信数据边界。
- 知识提取端到端测试使用确定性的模拟模型，不需要 API Key。
- 本地原料复扫和 MarkItDown 转换测试不调用模型。
- 开发与构建过程中不使用用户保存的真实 API Key，也不把真实原料提交给模型。
