# 知识库工坊

## 目标

知识库工坊把用户有权使用的本地原料转换为可审核的 Markdown 题目和知识文档。它不是无条件批量复制器，也不会把模型输出直接写入正式题库。

核心工具是 Microsoft 开源的 [MarkItDown](https://github.com/microsoft/markitdown)。项目固定使用 PyPI 的 `markitdown 0.1.6`，Python 要求为 3.10 或更高版本。MarkItDown 的定位是为文本分析和 LLM 流程生成 Markdown，并不保证面向排版的高保真还原。

## 流程

1. 原料扫描：读取路径、格式、大小和修改时间，不修改文件。
2. 本地转换：MarkItDown 在独立 Python 进程中生成原始 Markdown。
3. 内容分片：按段落拆为最多 12,000 字符的片段，单文件最多 60 片，避免无限请求。
4. LLM 提取：依据模式生成题目、知识、方法或规律候选。
5. 质量审校：高质量模式再次对照相同来源片段，删除无证据或字段不完整的候选。
6. 人工审核：用户检查内容、置信度、定位摘录和警告，并明确批准或拒绝。
7. 发布：只把批准项写入应用管理 Vault，随后使用正常 Vault 索引流程校验。

## 自定义项

- 产物模式：自动、题目、知识文档、仅转换。
- 质量流程：标准单阶段、高质量双阶段。
- 默认科目：自动、行测、申论、公共知识。
- 批次标签：附加到所有候选。
- 自定义整理要求：控制内容侧重点，例如优先提取公式、典型陷阱或申论规范表达。该要求不能取消证据、格式和审核约束。

## 安全与隐私

- 只调用 MarkItDown 的 `convert_local()`，不调用通用 URI 转换。
- 子进程使用参数数组并关闭 Shell，含空格和中文标点的路径不会被当成命令。
- 原料路径必须位于本次扫描根目录内，符号链接不会被跟随。
- 每个原料最大 256 MB，原始 Markdown 最大 20 MB，单批最多 500 个文件。
- API Key 只由 Electron 主进程通过 `safeStorage` 解密，永不传给 Python 转换器。
- 来源 Markdown、任务参数和候选 JSON 被包在明确的数据边界内，统一 Prompt 要求忽略材料内的任何指令。
- 原料和转换结果不会自动发布。批准动作和发布动作分离。

## 当前格式与限制

本地转换白名单包括 PDF、DOCX、PPTX、XLSX、XLS、HTML、CSV、JSON、XML、TXT、Markdown、EPUB、MSG 和 EML。

- 扫描式 PDF 没有文本层时，MarkItDown 可能返回空内容。工坊会在文本少于 50 字时阻止后续整理并提示 OCR。
- 图片当前标记为需要可靠 OCR。仅提取 EXIF 或让不确定的视觉模型猜文字不符合高质量入库要求。
- 视频当前跳过。视频转录需要独立的音轨提取、语音识别和时间戳校验流程。
- 未完成下载文件、符号链接和超大文件会在扫描列表中解释原因。
- LLM 整理会产生费用，并可能受服务商限速影响。先用 1-3 个文件验证 Prompt 和产物结构。

Microsoft 官方也明确提示 MarkItDown 以当前进程权限执行 I/O，应限制输入路径并优先调用最窄的本地转换 API。本项目按该建议实现。发布包不内嵌不可移植的虚拟环境，首次使用由界面在应用数据目录安装固定版本依赖。

2026-08-18 对开发环境原料的复扫验证结果为：438 个文件中 404 个可直接进入转换队列，包括 402 个 PDF 和 2 个 DOCX；未完成下载文件为 0。其余为 23 张图片、2 个未超限视频和 9 个超过 256 MB 的视频。此次复扫只读取文件元数据，没有转换正文，也没有调用任何模型。原料本身和包含本机路径的扫描产物均不进入开源仓库。

## 故障恢复

- 单文件失败不会停止其余文件。
- 可以停止批次。当前网络请求结束后，任务进入取消状态。
- 失败或取消的文件可以重试。
- 应用退出后，正在运行的文件标记为失败并提示重试，已完成的原始 Markdown 和候选产物保留。
- 转换目录可从任务区直接打开，便于人工检查和手动备份。
